# PLAN — Portfolio + Beat Store (virus404beats)

**Status:** All phases complete. Build green. Ready to deploy.
**Goal:** turn the static portfolio into a **portfolio + beat store**: dynamic music from YouTube + uploaded beats, a hidden admin dashboard (Google + OTP), streamable tagged previews (Cloudinary), and a manual buy flow (Email + WhatsApp).

**Principles:** everything free · secure by layers · easy to understand · easy to edit · easy to implement · nothing downloadable site-side.

---

## 0. TL;DR

| What | How | Cost |
|---|---|---|
| Hosting | Vercel (Hobby) | Free |
| Database | Turso (SQLite/libSQL) + Drizzle ORM | Free |
| Auth | Google OAuth (hand-rolled) + email OTP via Resend | Free |
| Media | Cloudinary (audio + covers), YouTube embeds | Free |
| Store page | `/beats` — priced beats, tagged preview streams, Buy buttons | — |
| Works page | `/works` — two columns: YouTube videos + uploaded MP3s | — |
| Admin | `/admin` (hidden) → Google login → OTP → dashboard | — |

No payments integration: buyers email/WhatsApp you, you negotiate and deliver the full file manually. Full files never touch the site.

## 1. Accounts to create first (all free)

1. **Vercel** — connect the GitHub repo, deploy (project already on `main`)
2. **Turso** — create database (nearest region to India), copy `DATABASE_URL` + auth token
3. **Cloudinary** — create account, note cloud name + API key/secret
4. **Resend** — verify your domain (or use shared domain), get API key
5. **Google Cloud** — OAuth app (Web client), `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET`, redirect to `/api/auth/callback`

---

## 2. How it works (simple mental model)

```
Visitor → /beats, /works (public, ISR cache 60s)
              ├── YouTube videos → embedded player (thumbnail + click-to-play)
              └── Uploaded beats → Cloudinary stream (tagged/looped preview)
                      └── Buy → prefilled Email + WhatsApp message (beat ID, title, price)
                                   ↓
You (manual) ← negotiate → deliver full file via WhatsApp/email/Drive

You → /admin (hidden, never linked) → Google login (email allowlist) → OTP (email)
        → dashboard: add/edit beats, works, prices, covers, top-10, text content
```

---

## 3. Security (5 layers)

1. `/admin` not linked anywhere (obscurity)
2. Google login — only emails in `ADMIN_EMAILS` env are allowed
3. OTP emailed after login (6 digits, hashed, 10 min expiry, 5 attempts)
4. Every `/api/admin/*` checks the signed session cookie + OTP-verified flag
5. Rate limits on login/OTP endpoints (Vercel built-in + in-DB counters)

**Decision point:** OTP must go to a **different email than your Google account** (same inbox = no extra security). Optionally swap email OTP for a TOTP app (Google Authenticator) later — stronger and free.

---

## 4. Tech decisions (locked)

| Decision | Choice | Why |
|---|---|---|
| DB | Turso + Drizzle | Free, serverless SQLite, zero ops, fits single-admin data |
| Auth | Hand-rolled Google OAuth + JWT cookie (`jose`) | No Auth.js/Next 16 compat risk; few deps; full control |
| OTP | Resend email | Free tier (100/day) is more than enough |
| Media | Cloudinary, **1 upload per beat** | Tagged/looped preview generated by delivery transform — no double uploads |
| YouTube | Manual video-ID entry | No API key, full control of order & top-10 |
| Embeds | Lite-youtube (thumbnail + click-to-load) | 20+ videos without slowing the page; one shared player for top-10 |
| Rendering | Public DB pages ISR `revalidate: 60` | Static speed, fresh content; hero stays static |
| Content | `site.ts` = defaults; DB overrides on top | Existing config system stays; dashboard edits win |
| No-download | Signed URLs + fetch protection + **tagged previews** | Ripping a tagged preview is worthless — that's the real protection |

## 5. Data (Turso tables)

- `beats` — title, meta, year, price, currency, cover, cloudinaryPublicId, youtubeId?, isTop, order, status (draft|published)
- `works` — kind (youtube|uploaded), youtubeId? / cloudinaryId?, title, meta, year, order, status
- `otps` — email, codeHash, attempts, expiresAt
- `content_overrides` — key, value(json): only services / hero / about (typed, not a page editor)
- `audit_log` — action, detail, createdAt (Phase 4)

## 9. Buy flow (how it works for the buyer)

1. On `/beats` → click **Buy** → two options:
   - **Email** — opens prefilled mail (subject: `Beat Purchase: {title} ({id})`, body: beat ID, title, price, license note)
   - **WhatsApp** — opens `wa.me` with the same info
2. You receive it and negotiate manually (price/license/usage)
3. On agreement you deliver the full file via WhatsApp/email/Drive — it never exists on the site
4. Preview stays the tagged/looped Cloudinary stream (not downloadable)
